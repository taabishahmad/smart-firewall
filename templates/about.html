How it works

From packet to verdict in four stages

Every connection on the monitored network passes through the same pipeline. Nothing is hard-coded to a rule — the decision to allow, flag, or block comes from a model that learned the difference between normal and hostile traffic.

01 · Capture

Packets are sniffed live and grouped into bidirectional flows with per-flow timing, byte counts, and TCP state.

02 · Features

Each flow becomes an NSL-KDD-style feature vector using two-second and hundred-connection rolling windows.

03 · Classify

A Random Forest scores the vector and returns a verdict with a confidence the operator can tune against.

04 · Enforce

Repeat offenders are dropped through pfSense or iptables, an alert is raised, and the event is logged.
